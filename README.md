# OpenTube

OpenTube is a self-hosted video community app with channels, uploads, playlists, Shorts, likes/dislikes, Watch Later, Premieres, a custom player and live broadcasts.

**Live streaming uses SSH101's free RTMP ingest and HLS playback.** OBS sends the broadcast to SSH101; viewers watch it inside the OpenTube player and chat. SSH101 is the streaming infrastructure only—the audience does not need to leave OpenTube.

## Deploy on Render

1. Upload this folder to your GitHub repository.
2. In Render choose **New → Blueprint** and select the repository (or create a Node web service with `npm install` and `npm start`).
3. Attach a PostgreSQL database and set `DATABASE_URL` (the Blueprint creates one when supported by your Render plan).
4. Set `ADMIN_PASSWORD`; `SESSION_SECRET` is generated by the Blueprint.
5. Deploy. The app creates/migrates its PostgreSQL tables on startup.

No Cloudflare API token, MediaMTX instance, Docker host or VPS is required for SSH101 streaming. Render only hosts the OpenTube website/API; SSH101 receives the RTMP video.

## Configure a free SSH101 live channel

1. Open [SSH101](https://ssh101.com/) and create a free channel. The SSH101 page says it provides RTMP ingest, HLS/DASH playback URLs and embed links for use in your own app/site.
2. In the SSH101 channel/control page, copy the **Streaming Publishing Point** (the channel name/key used as the OBS Stream Key) and the direct **HLS URL** ending in `.m3u8` / `playlist.m3u8`.
3. In OpenTube, sign in to your channel and open **Live**.
4. Enter a title, the SSH101 Publishing Point and the HLS `.m3u8` playback URL. Save the configuration.
5. Open OBS → **Settings → Stream** → Service **Custom**.
6. Use these values:
   - Server: `rtmp://ssh101.bozztv.com/ssh101`
   - Stream Key: the exact Publishing Point from SSH101
7. Click **Start Streaming** in OBS. OpenTube viewers can open the live card and watch in the OpenTube player with the built-in chat.

The current SSH101 Next-Gen site documents its RTMP endpoint as `rtmp://ssh101.bozztv.com/ssh101/<your_channel>` and gives an example HLS address shaped like `https://183.giatvcdn.com/ssh101/ssh101/<your_channel>/playlist.m3u8`. Use the exact endpoint and HLS URL shown for your own channel; if SSH101 gives you a different server address, use the server shown in its control room. SSH101's legacy service may show `rtmp://stream.ssh101.com/live` instead, so do not mix credentials/endpoints from the two interfaces.

Official references:
- [SSH101 Next-Gen](https://ssh101.com/) — free live streaming, RTMP in, HLS out, embed anywhere and OBS setup.
- [SSH101 legacy FAQ](https://v2.ssh101.com/faqs.php) — legacy ingest, channel creation and embed details.

## OBS suggestions

- Encoder: H.264 video + AAC audio.
- Rate control: CBR.
- Keyframe interval: 2 seconds.
- Start with 720p30 and approximately 1–2 Mbps video; SSH101's current guidance recommends around 1 Mbps (up to 2 Mbps) and lowering bitrate if playback is unstable.
- Start OBS only after saving the OpenTube HLS URL. HLS playback may take a short time to appear after the broadcast starts.

## Live features in OpenTube

- OpenTube-branded HLS player with play/pause, mute, volume and fullscreen.
- Live chat stored in PostgreSQL and polled every 2.5 seconds (not WebSocket instant messaging).
- Approximate live viewer count based on browser presence pings; this is not a billing-grade or exact unique-viewer metric.
- Channel subscriber count shown on the live page and live cards.
- Channel owner can update or remove the OpenTube connection without deleting their SSH101 channel.

## Existing community features

- Channels with private channel keys, uploads, playlists, comments, likes/dislikes and view counts.
- Admin panel with channel/video moderation and storage stats.
- Custom video player, history, resume position, autoplay, theater mode and keyboard shortcuts.
- Viewer subscriptions, saved videos / Watch Later and playlists.
- Shorts feed for portrait videos up to 3 minutes.
- Scheduled Premieres with countdown and premiere chat.

## Phone, tablet and app experience (v2)

- **Phone:** app-style bottom bar (Home, Shorts, Upload, Subscriptions, More), slide-over menu (swipe from the left edge), full-width cards, search overlay, bottom-sheet dialogs, and a video that stays pinned at the top while you read comments. Shorts fill the screen between the header and the bar.
- **Tablet:** compact icon rail, two to three column grid, and a side-by-side watch layout (stacked in portrait).
- **Touch player:** double-tap the left or right side to skip 10 seconds, tap to play or pause, controls fade away while playing.
- **Appearance sheet (the palette button):** Auto, Light or Dark, seven accent colours, pure-black AMOLED mode, compact grid and reduced motion. Saved on the device.
- **Look (v3):** animated aurora background tinted by your accent colour, glass header, menus and dialogs, glowing gradient buttons, spotlight hover on thumbnails, staggered card entrances, neon-rimmed Shorts and a glowing player with a gradient scrubber. Motion switches off with the Reduce motion setting or your system preference.
- **More:** loading skeletons, a "continue watching" progress bar on thumbnails, Share button, `/` to focus search, and an installable app (add to home screen) with an offline-ready shell.

## v4: live status, channel Live tab and Settings

- **Real "on air" detection.** The server checks each configured SSH101 HLS playlist (cached for 20 seconds) and only calls a channel live when a playlist is actually being served and has not ended. A channel that is set up but not broadcasting shows as OFFLINE.
- **Live look everywhere.** A live channel gets a spinning red ring and a LIVE label on its avatar, a red animated line on its channel card and channel header, a LIVE chip next to its name on video cards, a red counter on the Live menu item, and a "Live now" row (like stories) at the top of Home.
- **Live tab on every channel.** Shows the stream title, quality, viewers and a Watch live now button, or an offline card. Owners get a Manage stream shortcut.
- **Live alerts.** When a channel you subscribed to goes live you get a toast, and a browser notification if you enable them in Settings (works while OpenTube is open).
- **Settings page** (Settings in the menu, or All settings in the palette sheet): theme, accent colour, pure black, compact grid, animations; autoplay next, start playing on open, remember position, default speed; default Home order and hide Shorts; live badges and alerts; copy channel key, sign out, clear history/resume/likes, export your data, reset; install the app and refresh the offline cache.
- **Continue watching** shelf on Home for videos you stopped partway.

## Windows (.exe) and Android (.apk) apps

The apps are thin native shells around your live OpenTube site, so they always show the newest version and share the same videos, channels and live streams. They are built for free by GitHub, so nothing needs installing on your computer.

1. Deploy the site first (Render) and note its address, for example `https://opentube.onrender.com`.
2. Put this whole project in a GitHub repository. The workflow lives in `.github/workflows/build-apps.yml`.
3. On GitHub open **Actions → Build apps → Run workflow**, paste your site address and run it. After a few minutes the run page lists two downloads: **OpenTube-Windows** (installer and portable `.exe`) and **OpenTube-Android** (`OpenTube.apk`).
4. For a permanent download page, add a repository variable named `SITE_URL` (Settings → Secrets and variables → Actions → Variables) and push a tag such as `v1.0.0`. The files then appear under **Releases**. Set `APPS_URL` on Render to that Releases page to show a Download button in Settings.

Installing: Windows may show a SmartScreen warning for an unsigned app (More info → Run anyway). On Android, allow "install unknown apps" for your browser or file manager. The APK is debug-signed, which is fine for sideloading; publishing to Google Play needs your own release key.

Both apps need an internet connection because the videos live on your server. Desktop shortcut for testing: `cd desktop && npm install && OPENTUBE_URL=https://your-site npm start`.

## Settings

| Variable | Meaning |
|---|---|
| `DATABASE_URL` | PostgreSQL connection string |
| `ADMIN_PASSWORD` | Admin login password |
| `SESSION_SECRET` | Signs admin sessions |
| `MAX_MB` | Maximum upload size in MB (default 50) |
| `DATABASE_SSL` | Set to `1` if your PostgreSQL host requires SSL |

## Important limitations

- SSH101 is a third-party streaming origin. Availability, terms, bitrate, channel limits, CORS and playback URLs are controlled by SSH101 and may change. OpenTube cannot guarantee SSH101 uptime or quotas.
- The HLS URL must be reachable by viewers' browsers and allow cross-origin HLS playback. If it does not, use the iframe/embed option SSH101 provides, or contact SSH101 support.
- The live chat and approximate viewer count are OpenTube features; SSH101 does not provide the chat for this app.
- Videos are stored in PostgreSQL in this version. `MAX_MB` controls the per-file cap, but database size, memory and bandwidth limits still apply. Large-scale hosting needs object storage and a streaming upload path.
- Do not commit `.env` or share your channel key publicly. Treat the SSH101 Publishing Point as a private stream key.
